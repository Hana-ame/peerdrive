01

连上信令，拿到一个 id

怎么测

开两个标签页（或两台设备），各自等 open 拿到 id；只需一端填另一端的 id 点「连接」，另一端会收到被动接入。之后两边共用同一条全双工通道，都能发、都能收，不用互填——两端同时主动连反而会撞出第二条连接。若 file:// 下连不上，用 python -m http.server 起个本地静态服务再打开。

02

互传字符串

发送走 conn.send(text)，接收走 conn.on('data', …)。收到的内容一律用 textContent 渲染，不当 HTML 解析——对端字符串是不可信输入。

当前目标 （未连接） 双向 · UTF-8 字符串
还没有消息。
建立通道后，在下面输入任意字符串，回车或点「发送」。
conn.send(text) → conn.on('data')

换行用 Ctrl / ⌘ + Enter 插入；单条消息没有长度限制，但公共信令不负责转发内容，超大字符串受浏览器 DataChannel 缓冲限制。

03

配置：就这五个参数

PeerJS 客户端的默认值正好就是云信令，但这里全部显式写出来，免得换自建服务器时不知道改哪个。.env 里的 PEERDRIVE_PEERJS_URL 与 PEERDRIVE_SERVER_URL 分别对应下表两行。

参数值作用
host0.peerjs.com信令主机。备用 peersignal.moonchan.xyz（自建 PeerServer）。
port443云 PeerServer 只跑 443，端口被网络挡住就换自建服务。
path/PeerServer 挂载路径；/peerjs/id 返回候选 id，只供本端注册，不是在线 peer 列表。
securetrue用 https / wss。HTTPS 页面下必须开，否则混合内容被拦。
keypeerjs云服务器的 API key，只有 0.peerjs.com 需要；自建服务不用。
serializationjson连接选项，不是 Peer 选项。明确按 JSON 收发，载荷就是字符串。

最小实现

// 两端都跑这段；open 拿到的是本端已注册的 id
const peer = new Peer({ host:'0.peerjs.com', port:443, path:'/',
                       secure:true, key:'peerjs' });

peer.on('open', id => { /* 把 id 给对方 */ });
peer.on('connection', conn => bind(conn));   // 被动接入

const conn = peer.connect(remoteId, { serialization:'json' });
bind(conn);

function bind(conn) {
  conn.on('open', () => conn.send('hello'));  // 发字符串
  conn.on('data', text => console.log(text));          // 收字符串
}

库是本地的

peerjs.min.js（PeerJS 1.5.5，86,948 B）直接放在分支里，页面不依赖 unpkg / jsdelivr 才能加载；万一本地文件缺失，才回落到公共 CDN。信令服务器仍然要联网。

id 从哪来

GET /peerjs/id 返回的是候选 id：每次一个新 UUID，背后没有在线 peer，只给 new Peer() 注册用。要填的是另一端 peer.on('open') 拿到、已经注册成功的 id；把 curl 拿到的候选串填进输入框，只会得到 peer-unavailable。CI 里 curl 这个端点只为探活，不拿它建连。

04

一条字符串走过的路

信令只在前三步出现。通道一旦建立，PeerServer 就不在数据的路径上了——这也是「互传」和「经服务器转发」的区别。

01
注册

new Peer() 向 /peerjs/id 要一个候选 UUID 并注册，开 wss 长连接。

02
寻址

A 拿 B 的 id 调 peer.connect(B)，请求经信令转给 B。

03
协商

交换 SDP / ICE；默认 ICE 含 STUN 与 turn:0.peerjs.com:3478。

04
通道

DataChannel 打开，两端各持一个 conn，open 事件就绪。

05
互传

同一条 conn 全双工：两端都能 send / on('data')，不用互填 id。

谁在传

一条 DataChannel 就是全双工的：主动连的一方和被动接的一方都绑同一套 open / data / close / error，所以谁都能先发，不用两端互填 id。

谁不在传

PeerServer 只做 id 分配与信令转发；字符串走 DTLS 加密的 DataChannel，不经它，也不落盘。

05

边界与取舍

这是一个连通性验证模块，不是传输层。写下来的目的是让下一个改它的人知道哪里会响。

边界含义
公共信令无认证0.peerjs.com 是免费公共服务，id 随机分配、不校验身份。任何知道 id 的人都能连进来；不要用它传敏感内容。
id 不是身份每次新建 peer 都换一个 UUID，重连也可能变。要认人得在连接 metadata 里带自己的标识，别拿 id 当账号。
候选 id 不是连接目标/peerjs/id 返回的 UUID 只用于本端注册，背后没有在线 peer；填它去连接必然 peer-unavailable。要填的是另一端 open 后显示的 id。
跨 NAT 依赖 TURN对称 NAT / 严格防火墙下直连会失败，流量要走默认 TURN。TURN 不可用时只剩「拿到 id 但连不上」。
只传字符串没有文件分片、没有媒体流、没有二进制协议。要传文件得另定编码（base64 或 Blob）与分块。
生产换自建 PeerServer页面里「信令」下拉可切到 peersignal.moonchan.xyz；自建服务不需要 key，路径按部署调整。
页面需安全上下文HTTPS 或 localhost 下最稳；file:// 在部分浏览器会拦 WebRTC，起本地静态服务即可。
对端内容不可信消息用 textContent 渲染，日志同理；不拼接 innerHTML，避免把收到的字符串当脚本执行。

一句话

这个分支只回答一个问题：0.peerjs.com 能不能把两个页面连起来、把字符串送过去。其余——身份、可靠传输、文件——都属于别的模块。
