## 1. 核心动机与设计决策

### 1.1 为什么选择 sha 级粒度而非条目/容器级？
在 #111 的初步设想中，权限曾被构想为「合集 + 条目（文件）+ 目录」。但在 Peerdrive 的内容寻址架构下，这一粒度存在严重弊端：

| 维度 | 条目/容器级（Entry-level） | 内容地址级（SHA-level，本规范） |
|---|---|---|
| **权限绑定目标** | 集合内的某一个相对路径条目 | 内容哈希（SHA-256）本体 |
| **同一内容出现在多个集合** | 容易出现权限漂移（如 A 集合公开、B 集合私有导致泄漏） | **权限必然全局自洽**，消除配置冲突隐患 |
| **跨节点分发与同步** | 权限依赖外层容器打包，难以脱离元数据独立验证 | **权限随内容走**（Content-Bound Capability） |
| **数据表模型** | 需复合键 `(collection_id, entry_idx)`，级联迁移复杂 | `sha_acl(sha, principal, actions)`，与 `sha_tags` 同构 |

**核心原则**：SHA-256 是唯一不可变的内容地址。依据 #121 的「元数据内容寻址化」原则，数据与元数据均以 SHA 形式存入 CAS（内容寻址存储），因此**访问控制语义必须直接附着于 SHA 本体**。

## 2. 数据源（Source）类型推断默认权限

权限体系秉持「零配置开箱即用」原则：**未显式配置 ACL 时，根据 Source 的 `Type()` 自动推断默认权限**，避免强制用户为每个文件手工打标。

### 2.1 默认权限推断矩阵

| 数据源类型 (`Source.Type()`) | 默认权限级别 | 核心依据与语义 |
|---|---|---|
| `ech` | **`unlisted`** | ECH（Encrypted Client Hello）域前置 URL 属于**不公开列出、但持有有效哈希即可访问**的典型代表。 |
| `url`（回环地址） | **`private`** | Base URL 为 `127.0.0.1` / `[::1]` / `localhost` 时，不具备物理跨主机可达性，默认严禁外部非受信对端访问。 |
| `url`（外网地址） | **`unlisted`** | 公网直接可达的外部 URL 资源，未发布进公开合集前保持非列出状态。 |
| `local` | **`private`** | 本地文件系统目录，默认仅供本机用户及持有凭据的授权者操作。 |
| `sha` | 继承来源元数据 | 本地已入库的 CAS 块，其默认可见性直接继承写入时的元数据声明。 |
| `openlist` | **`unlisted`** | 爬虫与目录镜像源，抓取的内容默认不向公网自动广播，需显式加入公开清单。 |
| `peer` | **`private`** | 来自其他对端 P2P 镜像的缓存数据，默认受保护，除非所属集合显式共享。 |

### 2.2 回环地址自动判定实现机制
在 `URLSource` 注册与加载时，通过解析 Base URL 进行网络拓扑识别：
```go
// 判定逻辑伪代码：
u, err := url.Parse(templateURL)
if err == nil {
    host := u.Hostname()
    ip := net.ParseIP(host)
    if host == "localhost" || (ip != nil && ip.IsLoopback()) {
        source.SetDefaultVisibility(model.VisibilityPrivate)
    }
}
```

## 3. 临时提权机制（Ephemeral Elevation via Share Links）

当某个 `private` 内容被用户主动创建了外部分享（`share_links`）时，系统需要允许外部持有链接者访问，同时保证安全性与可逆性。

### 3.1 派生状态设计（不入库原则）
系统**严禁**将临时分享直接写入持久化 `sha_acl` 表（避免撤销分享后权限残留）：
- **提权只存活于活跃分享的生命周期**；
- 提权判定为**计算型派生状态**（Derived State），而非修改数据库中的持久 ACL 实体；
- 当分享链接被删除或过期时，提权自动瞬间归零。

### 3.2 判定流程
```text
ACL 检查: 该 SHA 为 private 且请求方未授权？
  │
  ├─ 检查: 该 SHA 是否属于当前某个有效活跃的 Share Link？
  │    ├─ 是  ──> 临时提升为 unlisted，放行读取
  │    └─ 否  ──> 拒绝访问，返回 404 语义
```

### 3.3 回环 URL 的提权安全约束
- 若 Provider 为 `sha256`（文件 CAS）：临时提权完全有效；
- 若 Provider 为 `url` 且属于本地回环：只有在存在活跃的端口转发隧道（`p2p_forward`）时，该提权才具有可达性；否则系统应阻止创建该类分享，防止对端拿到无法连通的死链接。

## 4. 控制面门禁与游客可见性三轴模型

为解决「未验证即游客」的可见性与权限边界，确立正交的三轴访问控制模型：

```text
┌──────────────────────────────────────────────────────────────────┐
│                           三轴访问控制模型                        │
├─────────────────┬────────────────────────────────────────────────┤
│ 1. 控制面 (Verb) │ create / upload / delete / sync / pull / fwd-* │
│                 │ 强制要求验证（PSK 或 用户身份凭据）；游客全面拒绝   │
├─────────────────┼────────────────────────────────────────────────┤
│ 2. 可见性 (List) │ list / info / search                           │
│                 │ 游客仅返回 public 条目；unlisted 和 private 裁剪│
├─────────────────┼────────────────────────────────────────────────┤
│ 3. 取数面 (Req)  │ req (按 SHA 提取内容)                          │
│                 │ public 开放；unlisted 持哈希即取；private 404   │
└─────────────────┴────────────────────────────────────────────────┘
```

### 4.1 权限档位三元对照表

| 权限档位 | 出现在列表/搜索中？ | 按 SHA 直接提取内容？ | 是否需要凭据认证？ |
|---|---|---|---|
| **`public`** | ✅ 允许显示 | ✅ 允许所有人提取 | 否 |
| **`unlisted`** | ❌ 隐藏不列出 | ✅ **持有有效 SHA 即可提取** | 否 |
| **`private`** | ❌ 隐藏不列出 | ❌ 未授权者一律拒绝 | **是（强制 PSK / 身份令牌）** |

> **关键语义**：`unlisted` 允许持有 SHA 直取，这与现代分享机制（如非公开链接、Pastebin、网盘链接）语义一致。持有 SHA 即视为持有不可伪造的 Bearer Token。

### 4.2 防枚举 404 安全语义
当未验证的游客试图通过 `req` 读取一个 `private` 的 SHA 内容时：
- 服务端**不得**返回 `403 Forbidden` 或 `PSK_REQUIRED`；
- 服务端统一返回 **`404 Not Found` / `FILE_NOT_FOUND`**；
- **防枚举保证**：攻击者无法通过遍历 SHA 探测目标节点是否存在特定私有文件。

## 5. 存储架构与表结构设计

复用现有成熟的 `sha_tags` 表设计（#91 / #157），以同构的轻量级关系表承载：

```sql
-- 内容地址级访问控制列表
CREATE TABLE IF NOT EXISTS sha_acl (
    sha       TEXT NOT NULL,          -- 内容哈希 (64 hex)
    principal TEXT NOT NULL,          -- 授权主体: user:<name> | peer:<id> | anonymous
    actions   TEXT NOT NULL,          -- 授权动作: view | read | write | manage
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (sha, principal)
);

CREATE INDEX IF NOT EXISTS idx_sha_acl_sha ON sha_acl(sha);
```

### 5.1 增量存储原则（仅记录偏离）
- 绝大多数文件的权限由 Source 类型与默认规则决定，**零入库开销**；
- 只有当管理员或创作者显式指定了偏离默认值的 ACL 时，才在 `sha_acl` 写入记录；
- 维持数据库极致小巧与高效。
