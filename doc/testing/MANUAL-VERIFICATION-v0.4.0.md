# Peerdrive v0.4.0 人工测试与核心功能验证指南

> 本指南针对 **Peerdrive v0.4.0** 引入的核心能力（遥控投屏、P2P 流切片广播、端口转发、aria2c 插件、移动端 UX 与攻击对抗防线）提供标准化的人工验证流程与测试检查清单。

---

## 1. 验证前准备：快速启动本地测试环境

### 方式 A：单二进制一键启动（推荐）
```bash
# 1. 编译本地单二进制
cd back && go build -tags nosqlite -o ../peerdrive ./cmd/peerdrive/ && cd ..

# 2. 启动自托管信令服务器（端口 9000）
./peerdrive signal -port 9000 &

# 3. 启动节点 A（主节点 / 网盘节点，端口 3000）
PEERDRIVE_PORT=3000 \
PEERDRIVE_PEERJS_HOST=127.0.0.1 \
PEERDRIVE_PEERJS_PORT=9000 \
PEERDRIVE_REMOTE_CONTROL_ENABLE=true \
PEERDRIVE_REMOTE_CONTROL_TOKEN=secret-token-123 \
PEERDRIVE_FORWARD_RULES='{"fwd-key-abc":[8080]}' \
./peerdrive serve &

# 4. 启动前端（若需调试最新前端热重载）
cd front && npm run dev &
```

## 2. 核心功能人工验证矩阵

### 模块一：遥控投屏与展示大屏联动（Display & Remote Control）
> **背景**：Issue #234, #243。多端受控屏幕联动，支持在 Drive 界面直接控制远程屏幕/展示大屏。

- [ ] **场景 1.1：展示大屏开启与注册**
  - **操作**：打开浏览器访问 `http://localhost:3000/display`（或前端大屏展示路由）。
  - **预期**：大屏正常初始化，显示当前频道（默认 `default`）及待机就绪状态，控制台输出 `registered screen`。
- [ ] **场景 1.2：网盘文件一键投屏**
  - **操作**：在另一个设备/标签页打开网盘文件列表，右键点击图片/视频文件，选择「投屏到大屏」。
  - **预期**：展示大屏即时加载该文件并开始渲染/播放，无须人工刷新大屏页面。
- [ ] **场景 1.3：远程播放同步控制**
  - **操作**：在控制端点击「暂停」、「播放」、「音量调节」或拖动进度条。
  - **预期**：大屏画面音画同步响应，播放状态双向一致。
- [ ] **场景 1.4：受控模式安全基线（关键约束）**
  - **操作**：针对未打开 `/display` 处于普通页面的 Session 发送投屏指令。
  - **预期**：明确提示被拒绝（`target session is not in display mode`），严禁静默劫持未受控客户端。

---

### 模块二：P2P 直播源与文件 SHA 切片广播（Live Stream Chunk Distribution）
> **背景**：Issue #244。以服务 Peerdrive 文件的方式提供文件 SHA 切片，多节点互抓流媒体分片。

- [ ] **场景 2.1：流频道创建与订阅**
  - **操作**：通过接口或界面创建流频道 `live-radio`，订阅者节点接入并订阅该频道。
  - **预期**：订阅者收到 `manifest` 播放清单，显示频道当前活跃状态。
- [ ] **场景 2.2：切片持续广播与去中心化拉取**
  - **操作**：广播源节点持续推送新切片 SHA（`StreamChunk`）。
  - **预期**：所有订阅节点实时收到切片通知，并自动通过 WebRTC DataChannel 跨节点抓取该文件分片并连续播放。
- [ ] **场景 2.3：防劫持与所有权保护**
  - **操作**：第三方未经授权节点尝试推流到正在活跃的频道或尝试关闭该流。
  - **预期**：操作被坚决拒绝（返回未授权），保护原主播频道不受篡改。

---

### 模块三：基于 PeerJS 的端口转发 TCP 隧道（Port Forwarding）
> **背景**：Issue #245。在 WebRTC DataChannel 上承载双向 TCP 隧道，提供 NAT 穿透。

- [ ] **场景 3.1：本地服务启动与白名单映射**
  - **操作**：启动测试 HTTP 服务 `python3 -m http.server 8080`；确认节点配有 `fwd-key-abc` 允许转发端口 `8080`。
- [ ] **场景 3.2：HMAC 握手与隧道透传**
  - **操作**：发起端出示 Key 发起 `fwd-open` 并完成质询响应，建立转发连接并请求数据。
  - **预期**：能够正常访问到目标端口的 HTTP 服务响应，流量双向透传顺畅。
- [ ] **场景 3.3：越权端口拦截与防重放**
  - **操作**：尝试请求未授权端口（如 `22`、`3306`）或重放先前握手。
  - **预期**：非白名单端口返回 `port not authorized`，已消费质询返回 `no challenge`。

---

### 模块四：aria2c 高速下载插件集成（aria2 Integration）
> **背景**：Issue #236。集成 aria2c 插件兼容能力，支持零依赖动态启闭。

- [ ] **场景 4.1：插件动态开关**
  - **操作**：在设置或传输管理中开启 aria2 开关，观察状态变更。
  - **预期**：开关响应迅速，状态持久化且无需重启节点服务。
- [ ] **场景 4.2：提交外部下载任务**
  - **操作**：输入合法的 `https://` 下载链接及保存文件名，提交下载任务。
  - **预期**：任务成功提交至 aria2 后台，前端传输列表呈现下载速度与进度。
- [ ] **场景 4.3：路径安全防御验证**
  - **操作**：提交恶意文件名（如 `../../evil.sh`）或非法协议（如 `file:///etc/passwd`）。
  - **预期**：服务端立即阻断并返回 `400 Bad Request`，严防下载目录逃逸与本地文件越权。

---

### 模块五：手机移动端网页 UX 与上下文菜单（Mobile UX & Context Menu）
> **背景**：Issue #235, #252。适配小屏幕移动端手势与右键/长按菜单扩展。

- [ ] **场景 5.1：移动端视口与抽屉导航**
  - **操作**：手机浏览器访问网盘，展开折叠菜单、切换网盘/市场/节点列表。
  - **预期**：无水平横向滚动溢出，抽屉导航平滑弹出，单手操作顺畅。
- [ ] **场景 5.2：文件右键与长按菜单**
  - **操作**：在文件项上鼠标右键（PC 端）或手指长按（移动端）。
  - **预期**：弹出自定义上下文菜单（下载、分享、投屏、重命名、删除），位置计算准确，点击外部区域自然收起。
