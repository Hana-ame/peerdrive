关键通信链路

1. 管理面（前端 ↔ 本地后端）— admin verb

  • front/ws.js → 本地 WS /ws/peer → transport/ws_session.go：admin/admin-resp/admin-bin 帧，内部转发 gin engine 复用全部 HTTP controller
  • 二进制上传：admin 声明帧（含 filename/size/field）→ 连续二进制帧；文件流响应：admin-bin 头 + 单二进制帧
  • 安全决策：仅本地 WS 会话可用；WebRTC 连接不实现管理 verb（防权限面暴露，serveAdmin 按会话 ID 拒绝非本地）

2. 数据面（后端 ↔ 对端节点）— WebRTC DataChannel

  • transport/peerjs_service.go 经 peerjs 库注册到信令（自托管 peerserver 或 0.peerjs.com），发现节点后建立 DataChannel
  • 文件拉取：req(64hex hash, offset, size) → meta/data×N/done|err；file_index 表 + seq 游标做增量索引同步（create/upload/list/info/delete/sync）
  • 端口转发 v2：fwd-open/challenge（HMAC 质询）+ 端口白名单

3. 内容来源（SourceManager）

  • cmd/server/main.go 装配：PeerJSService → router.SetPeerJSService → source.New() 注册 LocalSource（本地盘 + FileIndex）/ PeerSource（对端可寻址）/ URLSource（模板）→ router.SetSourceManager
  • 注意装配顺序：SetPeerJSService 必须在 SetupRouter 之前调用（路由注册时读取）

4. 节点发现

  • 自托管：peersignal.moonchan.xyz（WS 信令 + /discover/* API），PEERDRIVE_DISCOVER_URL 设置后优先于 MQTT
  • 公共：MQTT 分片房间发现（broker.emqx.io）

5. 独立包 peerdrive-media

  • 发布为 github.com/Hana-ame/peerdrive-media（tag v0.1.0），与主 repo 无运行时依赖；浏览器端 core.js 三入口（react/vanilla/node）
  • 协议与主 repo 数据面同源但独立实现：raw 序列化、连接级串行、64KB 块、bufferedAmount>4MB 背压
  • 文档：doc/REFACTOR.md §3.11（含浏览器 E2E 踩坑五连）

模块依赖方向

cmd/server ─┬─> repository（SQLite 初始化 + 匿名存储目录）
            ├─> transport.NewPeerJSService ──> router.SetPeerJSService
            ├─> source.New() ── LocalSource / PeerSource / URLSource ──> router.SetSourceManager
            └─> router.SetupRouter ──> controller ──> service ──> repository / transport / p2p_bt

cmd/peerserver ──> signalserver（自托管信令 + 发现 API），独立二进制独立部署

front：ws.js(admin) ──> back/transport/ws_session
       api.js(HTTP) ──> back/router/controller
       P2P 页面     ──> back/transport/peerjs_service（WebRTC 数据面，管理面不开放）

packages/peerdrive-media：浏览器 ⇄ Node（PeerJS 信令 + WebRTC DC），完全独立
